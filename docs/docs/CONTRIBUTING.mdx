# Contributing to Takeoff UI

Thank you for your interest in contributing to the Takeoff UI Design System!
Whether you’re a community contributor or a core team member, this guide will
help you navigate our project structure, issue management, commit message
guidelines, and pull request process.

---

## Project Overview

The Takeoff UI Design System is a monorepo built using:

- **Core Web Components**: Developed with [Stencil.js](https://stenciljs.com/)
  (`@takeoff-ui/core`)
- **Monorepo Management**: Managed with [Turborepo](https://turbo.build/)
  (`turbo`)
- **Framework-Specific Targets**:
  - `@takeoff-ui/react`
  - `@takeoff-ui/vue`
  - `@takeoff-ui/angular`
- **Tailwind Plugin**: `@takeoff-ui/tailwind`

**Directory Structure:**

```plaintext
packages/
├── core/      # Core web components
├── react/     # React wrapper library
├── vue/       # Vue wrapper library
├── angular/   # Angular wrapper library
└── tailwind/  # Tailwind plugin for the design system
```

## Issue Management

We use **GitHub Issues** for bug reports and feature requests. Before opening a
new issue, please search existing issues to avoid duplicates.

### Available Issue Templates

When you click **New issue** in our repo, choose one of the following templates
(they live under `.github/ISSUE_TEMPLATE/`):

- **Bug Report**
- **New Feature Request**

Follow the prompts in the template you select and fill in all required sections.

---

## For Community Contributors

### Claim an Issue

- Issues will be labeled by the Core Team first.
- Look for issues which are not labeled as **Core Team**, available issues can
  be self-assigned when identified.

### Branch Naming

Use the format:

```plaintext
{type}/{issue-number}-{short-description}
```

- `type` = feature, fix, docs, style, refactor, test, chore
- `issue-number` = the GitHub issue number (e.g. `123`)
- `short-description` = brief, kebab-case summary

Example:

```plaintext
feature/123-add-loading-state
```

### Creating a Pull Request

1. Push your branch to GitHub.
2. Click **Compare & pull request**.
3. Reference the issue in your PR title:
   ```plaintext
   #123: Add loading state to Button component
   ```
4. Fill out our PR template (you’ll see it pre-populated).

## Commit Guidelines

We follow a conventional-style commit format:

```plaintext
<type>(<scope>): <subject>
```

- **type**: feat, fix, docs, style, refactor, test, chore
- **scope**: affected package or area (e.g. `tk-button`, `core`)
- **subject**: short imperative description (≤ 75 chars)

**Examples:**

```plaintext
feat(tk-button): Add loading state animation
chore(deps): Bump stenciljs to v3.5.0
```

- Use **imperative mood** (“add”, “fix”, “update”)
- Capitalize the subject (no trailing period)
- If needed, include a body separated by a blank line
- Reference issues by number (e.g. `Closes #123`)

## Changesets

We use [Changesets](https://github.com/changesets/changesets) to manage
versioning and changelogs. Every PR that affects a publishable package **must**
include a changeset.

### When to Add a Changeset

- Any change to `@takeoff-ui/core`, `@takeoff-ui/react`, `@takeoff-ui/vue`,
  `@takeoff-ui/angular`, or `@takeoff-ui/tailwind`
- Bug fixes, new features, breaking changes, or dependency updates that affect
  public APIs

### When NOT to Add a Changeset

- Changes to demo apps (`angular-app`, `react-app`, `vue-app`)
- CI/CD configuration, README updates, or internal tooling that doesn't affect
  published packages

### How to Add a Changeset

Run the following command from the repository root:

```bash
pnpm changeset add
```

You'll be prompted to:

1. **Select affected packages** — choose which packages your change impacts
2. **Choose bump type** — `patch` (bug fix), `minor` (new feature), or `major`
   (breaking change)
3. **Write a summary** — a short description that will appear in the CHANGELOG

This creates a markdown file in the `.changeset/` directory. Commit it with your
PR.

### Bump Type Guide

| Change Type               | Bump    | Example                          |
| ------------------------- | ------- | -------------------------------- |
| Bug fix, style tweak      | `patch` | Fix button focus ring color      |
| New component, new prop   | `minor` | Add `tk-avatar` component        |
| Removed prop, renamed API | `major` | Rename `variant` to `appearance` |

### Empty Changesets

If your PR doesn't need a release (e.g., docs-only or test-only changes), run:

```bash
pnpm changeset add --empty
```

## Pull Request Guidelines

Our PR template will guide you through these sections:

```markdown
### Description

Explain your changes in 1–2 sentences.

### Related Issue

Closes #123

### Testing Steps

1. Step 1
2. Step 2

### Screenshots

![Component Preview](https://via.placeholder.com/400x200)
```

Make sure all CI checks pass and tests are up-to-date before requesting review.
